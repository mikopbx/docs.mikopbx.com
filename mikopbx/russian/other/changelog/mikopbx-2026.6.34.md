# MikoPBX 2026.6.34

Выпуск MikoPBX 2026.6.34 исправляет запись разговоров в сложных сценариях перевода и делает надёжнее переадресацию сотрудников. Усилена защита веб-интерфейса и REST API, добавлена поддержка облака Cloud.ru Evolution. Восстановлены установка с LiveCD и скачивание обновлений из веб-интерфейса.

### Записи разговоров и история вызовов

Если перевод отклонён в пользовательской подпрограмме диалплана, например через `Busy()` в `[internal-users-custom]`, запись разговора оператора возобновляется после возврата звонка. Ранее часть разговора после неудачного перевода терялась.

Перевод, принятый через перехват `*8`, теперь сохраняется в истории как отвеченный вызов с собственной записью. Ранее такой разговор отображался как пропущенный, а файл записи оставался на диске без привязки к звонку.

При прослушивании и скачивании записей в форматах MP3, WAV и OGG сконвертированный файл кешируется. Повторное воспроизведение и перемотка больше не запускают конвертацию заново, а временные копии не накапливаются на диске: кеш очищается автоматически.

### Переадресация и SIP

Настройки переадресации сотрудников применяются надёжнее. Они больше не теряются, если в момент сохранения телефония была недоступна, а отключённая переадресация перестаёт работать сразу, без перезапуска станции.

{% hint style="warning" %}
Если собственный диалплан читает переадресацию из базы Asterisk (`DB(FW...)`), его нужно доработать: значения теперь хранятся в глобальных переменных `FW_<номер>`, `FW_BUSY_<номер>`, `FW_UNAV_<номер>` и `FW_TIME_<номер>`.
{% endhint %}

Нельзя сохранить двух провайдеров с входящей регистрацией и одинаковым логином, а также провайдера, логин которого совпадает с внутренним номером. Ранее такая ошибка останавливала работу всех линий и сотрудников. Ручные параметры `set_var` в дополнительных настройках снова применяются, в том числе несколько строк подряд.

Транспорт TLS в карточке сотрудника объявлен устаревшим и не предлагается для новых сотрудников. Для подключения по TLS укажите в SIP-клиенте имя пользователя в формате `номер-TLS`, например `105-TLS`, с тем же паролем. Сотрудники, у которых TLS уже выбран, получают предупреждение в карточке и в уведомлениях.

Внешний адрес станции для NAT больше не подставляется из имени хоста. Ранее это могло нарушить работу звонков за NAT и подключений по TLS. Ссылка в предупреждении о слабом SIP-пароле снова открывает карточку нужного сотрудника.

### Безопасность

Встроенная защита от атак проверяет тело запроса целиком, включая запросы `DELETE`. Проверка выполняется после блокировок и ограничения частоты запросов и не создаёт лишней нагрузки при подборе. Запросы к REST API больше 4 МБ отклоняются с понятной ошибкой.

Служебные ссылки на просмотр записей разговоров больше не доступны из сети, а скачивание архивов системных журналов ограничено только сформированными архивами. На Alibaba Cloud имя хоста, содержащее идентификатор экземпляра, больше не используется: идентификатор служит начальным паролем и не должен отображаться на странице входа.

### Облако, хранилище и обновление

Добавлена автоматическая настройка станции в облаке Cloud.ru Evolution, включая SSH-ключи из параметров виртуальной машины.

Для подкачки используется сжатая область в оперативной памяти. Файл подкачки на диске задействуется только при её заполнении, что снижает износ флеш-накопителей.

Восстановлено скачивание обновления из веб-интерфейса: ранее нажатие кнопки не запускало загрузку. Восстановлена установка с LiveCD: установщик больше не завершается сам, не дождавшись выбора диска и подтверждения.

Системный журнал хранит девять архивных частей вместо двух, поэтому на загруженной станции доступна история за более долгий срок. После сброса к заводским настройкам журналы продолжают записываться.

### Лицензирование

Подготовлен новый механизм подтверждения лицензии. Он поддерживает работу без доступа к интернету: файл-запрос скачивается на странице лицензирования, обменивается в кабинете лицензирования на файл-ответ и загружается обратно. По умолчанию механизм не активен.

Ключ лицензии и форма пробной лицензии проверяются до обращения к серверу, поэтому ошибки ввода сообщаются сразу.

### Для разработчиков

REST API модулей возвращает корректные HTTP-коды ошибок вместо `200` при `result: false`. Пустые JSON-объекты в ответах больше не превращаются в массивы. При превышении времени ожидания ответ имеет код `504`, при перегрузке очереди - `503`.

Загрузка файлов частями отправляет блоки не больше 10 МБ. Предупреждение об обновлениях модулей снова появляется после очистки кеша. Обновление времени последнего использования API-ключа работает и на установках с файловой системой только для чтения, например в LXC.
