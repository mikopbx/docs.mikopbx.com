# MikoPBX 2026.4.47

Выпуск MikoPBX 2026.4.47 повышает надёжность записей разговоров, переводов и перехвата вызовов. Добавлено автоматическое восстановление зависших локальных AMI-соединений, исправлено применение изменений модулей без перезагрузки станции, усилена безопасность REST API и облачных установок. Также улучшены маршрутизация, работа хранилища, сетевые настройки и веб-интерфейс.

### Записи разговоров и переводы

Исправлено продолжение записи после неудачного сопровождаемого перевода на очередь или группу вызова. Если ни один сотрудник не ответил и звонок вернулся к оператору, запись возобновляется в исходном файле с сохранением раздельных аудиодорожек. Ранее в таком сценарии вторая часть разговора могла остаться без записи, а длительность в истории вызовов отображалась некорректно.

При успешном переводе на очередь выход переводящего сотрудника из разговора больше не завершает CDR ответившего сотрудника раньше времени. Итоговая запись сохраняется, а длительность учитывает весь разговор до фактического отбоя. Улучшено сопоставление участников сопровождаемого перевода, в том числе при параллельном вызове нескольких сотрудников.

Восстановлена запись ответивших вызовов в сценариях перехвата и умной маршрутизации Smart IVR, где соединение создаётся через служебный Local-канал. Запись запускается на реальном SIP-канале сотрудника и продолжает работать после удаления промежуточного канала. При обычном перехвате используется уже выбранный файл записи, что предотвращает потерю или подмену аудио.

Для конференций исправлены ссылки на запись в истории вызовов. Участники одной конференции теперь используют существующий общий файл, вместо ссылок на отдельные файлы, которых нет на диске.

### История вызовов и интеграции

После завершения звонка через очередь или перевод оставшиеся временные CDR-записи закрываются по событию окончания всей цепочки вызова. Это устраняет записи, которые продолжали выглядеть незавершёнными после отбоя. Несколько фоновых процессов больше не могут одновременно взять одну и ту же завершённую запись в обработку. Если перенос в основную историю не удался, данные остаются во временной таблице для повторной попытки.

У перехваченных вызовов исправлен расчёт длительности разговора: завершение промежуточного канала больше не обрывает её через доли секунды после ответа. При ответе через `*8` или перехват супервизором в истории отображается имя сотрудника, который действительно принял вызов, а не сотрудника, у которого его перехватили. Сохраняются SIP Call-ID, необходимые интеграциям для сопоставления звонка с данными провайдера.

При скачивании записи в веб-интерфейсе показываются процент загрузки, скорость и примерное оставшееся время. Если сервер не передал размер файла, отображаются загруженный объём и скорость. Пока файл скачивается, кнопка защищена от повторного нажатия; после завершения или ошибки она снова становится доступной.

В метаданные стереозаписей WebM добавлены номера участников для левого и правого каналов: `CALL_LEFT_NUM` и `CALL_RIGHT_NUM`. Системы транскрибации и CRM могут определять, кому принадлежит каждая дорожка, без предположения, что сотрудник всегда находится на одной стороне записи. Для записей, у которых сторона не определена, эти метки не добавляются.

### Восстановление AMI-соединений

Улучшено восстановление соединений с Asterisk Manager Interface после разрыва или ошибки чтения и записи. Неисправный сокет закрывается, а повторное подключение использует исходные параметры и учётные данные. При запуске дочерних процессов служебные AMI-сокеты больше не остаются открытыми в унаследованных процессах.

Добавлен мониторинг сессий, которые перестали читать события Asterisk и накопили очередь неотправленных данных. Станция сначала фиксирует проблему в журнале, а при устойчивом зависании и подтверждённых признаках устаревшего соединения автоматически отключает локальную сессию. Автоматические отключения ограничены по частоте; внешние AMI-клиенты только диагностируются и не отключаются этим механизмом.

Перед автоматическим отключением публикуется событие `AmiSessionWatchdogDisconnect`, а результат операции записывается в системный журнал. Это помогает разработчикам интеграций и администраторам отличить восстановление зависшей сессии от обычного сетевого обрыва.

Исправлены накопление одинаковых фильтров при проверке AMI-соединения и разбор списков событий. Сохранена совместимость с модулями, которые используют собственные классы подключения к Asterisk Manager.

### Маршрутизация, очереди и IVR

Для SIP-провайдеров с входящей регистрацией выделены отдельные контексты диалплана. Такие провайдеры больше не объединяются только по совпадению адреса сервера. Это предотвращает смешивание входящих маршрутов и настроек разных учётных записей на одном хосте.

CallerID и DID теперь извлекаются из заголовков провайдера до проверки нерабочего времени и вызова обработчиков модулей. Даже если звонок завершается объявлением вне рабочего времени, история вызовов и интеграции получают реальный номер звонящего вместо имени транка. При выборе другого источника CallerID сохраняется переданное провайдером имя абонента.

Исправлено отображение номеров модулей в списках назначения. Настроенные направления снова доступны при выборе получателя во входящих маршрутах, очередях и других сценариях переадресации.

В веб-интерфейсе можно сохранить очередь без сотрудников, если задано направление для звонков в пустую очередь. При отсутствии и сотрудников, и такого направления форма сообщает об ошибке. IVR-меню без выбранного приветствия больше не воспроизводит случайный первый звуковой файл из базы.

### Работа с модулями

После установки или обновления включённого модуля фоновые процессы перечитывают его код и заново формируют необходимые конфигурации Asterisk. Исправление применяется и при повторной установке той же версии: изменения больше не остаются незаметными до перезапуска станции. После включения и выключения модуля обновляются также процессы REST API и наблюдения за службами.

Потеря кеша состояния модулей после перезапуска Redis или очистки кеша больше не мешает применению последующих изменений. Исправлен цикл перезапусков процесса обработки настроек, из-за которого задания перезагрузки конфигурации могли выпадать из обработки. Длительная штатная операция больше не считается зависанием после одного пропущенного ответа на проверку.

Индикатор установки теперь сохраняется после подтверждения запуска фоновой операции и показывает ход её этапов. Событие без дополнительных данных об этапе больше не вызывает ошибку JavaScript и не замораживает полосу прогресса.

В системном журнале фиксируется, кто запустил установку, удаление, включение или выключение модуля: пользователь, API-ключ либо внутренний процесс станции. При массовом обновлении сведения об инициаторе сохраняются для каждого модуля.

### Усиление безопасности

В облачных установках со стандартным веб-паролем, совпадающим с идентификатором виртуальной машины, после входа требуется сменить пароль. До его замены переходы по веб-интерфейсу направляют администратора на вкладку паролей в общих настройках. Проверка распознаёт как старый формат хранения пароля, так и SHA-512-хеш; установки Docker, LXC и системы без облачного идентификатора под это требование не попадают.

Закрыты возможности внедрения команд через параметры снятия блокировки Fail2Ban и внедрения строк диалплана через PIN конференции, настройки извлечения CallerID/DID и SIP-заголовок перехвата `X-CHAN-ID`. Усилена проверка названий очередей и идентификаторов VLAN.

Для приложений диалплана запрещены идентификаторы с попытками выхода за пределы каталога AGI-скриптов. Скрипты записываются через временный файл с последующей заменой, что также исключает чтение частично записанного содержимого.

Импорт сотрудников из CSV принимает только файлы, загруженные в предназначенный для этого каталог, и не позволяет подставить произвольный путь на сервере. Предварительный просмотр больше не перезаписывает исходный CSV при преобразовании кодировки.

Усилены проверки содержимого загружаемых аудиофайлов и путей перед конвертацией. Сохранение и удаление звуковых файлов ограничено управляемыми каталогами; клиент больше не может назначить произвольный путь через REST API.

Служебный NATS-сервер и его HTTP-интерфейс теперь по умолчанию слушают только локальный адрес. Это закрывает доступ к ним из сети в окружениях, где системный Firewall отключён или недоступен, в том числе в контейнерах.

### Fail2Ban, вход и права доступа

Fail2Ban больше не блокирует администратора из-за кратковременной недоступности Redis, тайм-аута внутреннего сервиса, отказа доступа к каналу событий или отсутствующего статического файла страницы. Проверки подозрительных запросов и сканирования сохраняются. При сбое Redis веб-защита не повторяет длительное подключение на каждом запросе и записывает предупреждение вместо потока ошибок, которые раньше могли привести к блокировке адреса.

После истечения сессии или потери её данных браузер возвращается к форме входа, а устаревшая cookie очищается. Для AJAX-запросов потеря сессии возвращает `401`, недостаток прав — `403` с сообщением об ошибке. Отказ в доступе больше не разлогинивает пользователя с действующей сессией, а несколько одновременных ошибок авторизации вызывают только один выход.

Для пользователей с ограниченными правами переход после входа учитывает настроенную домашнюю страницу. На странице отказа в доступе доступен выход из системы. Описания REST-разрешений локализованы, а унаследованные заглушки модулей больше не появляются в списке как реальные API-методы.

### Сеть, хранилище и обновление

Изменение только режима или ручных параметров IPv6 больше не перезапускает IPv4 DHCP и не отключает все сетевые интерфейсы. Обновляется IPv6 на нужном интерфейсе, поэтому веб-интерфейс, открытый по IPv4, не теряет соединение при сохранении таких настроек. Исправлена подпись маски подсети `/23`.

На старых установках с отдельным диском хранилища исправлен выбор раздела после смены имён дисков, например `/dev/sda` и `/dev/sdb`. Станция ищет подходящий раздел с данными MikoPBX на другом диске и после успешного подключения сохраняет его UUID. Если настроенный UUID не найден, раздел системного диска больше не подставляется вместо отсутствующего хранилища.

Восстановлена загрузка образов обновления из macOS, где браузер определяет `.img` как `application/x-apple-diskimage`. Исправлена передача категории и MIME-типа при загрузке файлов частями. Существующие API-клиенты, которые не указывают категорию, снова могут загружать файлы; основные ограничения на опасные расширения сохраняются.

### Исправления веб-интерфейса

Длинные имена абонентов в истории вызовов и названия IVR-меню больше не растягивают таблицы за пределы экрана и не скрывают кнопки редактирования, копирования и удаления. Полное имя доступно при наведении, а длинные направления в таблице IVR переносятся внутри ячейки.

Восстановлены поиск и сортировка на странице нерабочего времени: запросы больше не обращаются к отсутствующему столбцу базы данных. Поиск в верхнем меню не открывает список самопроизвольно при получении фокуса.

Для сотрудников допускаются внутренние номера длиной до 11 цифр. Исправлена оценка сложности длинных случайно сгенерированных SIP-паролей: короткая последовательность или три одинаковых символа внутри такого пароля больше не делают его автоматически слабым. Проверки простых и предсказуемых паролей сохраняются.

В настройках SSH можно добавлять публичные ключи аппаратных FIDO-устройств типов `sk-ssh-ed25519` и `sk-ecdsa-sha2-nistp256`. В общих настройках облачной станции вместо служебного ключа перевода показывается понятное описание стандартного пароля.

### REST API и звуковые файлы

При сохранении звукового файла поле `path` теперь доступно только для чтения. Для привязки нового аудио нужно передать `conversion_id`, полученный после конвертации: он действует 15 минут и используется один раз. Путь по-прежнему возвращается в ответах API для чтения и воспроизведения. Интеграциям, которые раньше передавали путь при сохранении, необходимо перейти на `conversion_id`.

Восстановлена совместимость скачивания файлов со старыми модулями, которые возвращают прежний формат `fpassthru`. Идентификаторы ресурсов проверяются без предварительного удаления пробелов и управляющих символов, чтобы некорректные значения отклонялись, а не превращались в другой допустимый идентификатор.

### Стабильность системы и консоль

События изменения настроек теперь отправляются после подтверждения транзакции базы данных. Фоновые процессы больше не начинают пересоздание конфигурации по данным, которые ещё не сохранены или впоследствии будут отменены.

Nginx применяет проверенную конфигурацию плавной перезагрузкой с сохранением существующих соединений. Если веб-сервер остановлен, станция запускает его через Monit. Снижено потребление памяти процессом системных рекомендаций и проверкой паролей по словарю: большой словарь больше не загружается целиком в память PHP для каждого поиска.

Очистка временных ссылок CDR больше не сканирует весь кеш для каждого ответа и не запускает отдельную проверку открытых файлов для каждой ссылки. Это уменьшает нагрузку при большом количестве звонков. Из системного журнала убраны штатные сообщения проверок доступности SSH.

В консольном меню исправлена обработка лишнего Enter после выбора пункта цифровой клавишей. Он больше не подтверждает следующий запрос автоматически, не закрывает экран состояния и не выбирает диск по умолчанию в мастере установки или подключения хранилища.
