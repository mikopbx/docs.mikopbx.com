# REST API

Модуль «Облачная транскрибация» отдает готовые расшифровки звонков в читаемом виде — для CRM, аналитики или другого модуля на той же АТС (именно так модуль «ИИ Супервизор» получает расшифровки).

Базовый путь:

```
/pbxcore/api/v3/module-cloud-speech-to-text
```

## Ключ интеграции

Для чтения расшифровок нужен специальный ключ — обычные ключи с широкими правами модуль отклоняет.

1. Откройте **Система → API-ключи** и создайте ключ **без** полных прав.
2. Сетевой фильтр ключа — «localhost».
3. В разрешениях оставьте единственную строку — чтение `/api/v3/module-cloud-speech-to-text/call-transcripts`.

Такой ключ принимает запросы только с самой АТС. Если внешняя система работает на другом сервере, поднимите до АТС SSH-туннель (`ssh -L 8080:127.0.0.1:80 адрес-атс`) и обращайтесь к `http://127.0.0.1:8080`.

{% hint style="info" %}
Ответы обернуты в стандартный конверт: `result` (успех или нет), `data` (данные) и `messages` (текст ошибки). Ниже описано содержимое `data`.
{% endhint %}

## Список расшифровок

```bash
curl -H "Authorization: Bearer КЛЮЧ_ИНТЕГРАЦИИ" \
  "https://адрес-атс/pbxcore/api/v3/module-cloud-speech-to-text/call-transcripts?limit=50&offset=0"
```

Параметры: `limit` (от 1 до 200, по умолчанию 50), `offset`, а также `from` и `to` — период в виде времени Unix. Каждый элемент содержит идентификатор расшифровки `aggregate_id` (он нужен для получения полного текста), `call_id`, `revision` и дату звонка. Объект `pagination` показывает общее количество.

## Полная расшифровка

```bash
curl -H "Authorization: Bearer КЛЮЧ_ИНТЕГРАЦИИ" \
  "https://адрес-атс/pbxcore/api/v3/module-cloud-speech-to-text/call-transcripts/0192f0c1-a2b3-4c5d-8e9f-0a1b2c3d4e5f"
```

Передайте `aggregate_id` из списка или события. В ответе:

* `transcript.segments` — все фразы с таймкодами, каналом и участником;
* `transcript.turns` — фразы, объединенные в реплики;
* `transcript.text` — весь текст одним куском;
* `call` — направление звонка, внутренние номера сотрудников и номера собеседников;
* `recognition` — язык и модель распознавания.

Параметром `?revision=N` можно запросить конкретную версию; по умолчанию возвращается последняя опубликованная.

## Событие о новой расшифровке

```bash
curl -H "Authorization: Bearer КЛЮЧ_ИНТЕГРАЦИИ" \
  "https://адрес-атс/pbxcore/api/v3/module-cloud-speech-to-text/call-transcripts:events?limit=100"
```

* Первый запрос — без параметра `cursor`, он вернет события с самого начала. Передавайте `next_cursor` из ответа в следующем запросе и сохраняйте его только после успешной обработки всех полученных событий.
* `call-transcript.completed` и `call-transcript.updated` — расшифровка готова или обновлена; после них запрашивайте полный текст.
* `call-transcript.deleted` — расшифровка удалена; в таких событиях `call_id` и хеши скрыты.

## Как не обрабатывать одно и то же дважды

* `semantic_hash` — хеш содержимого расшифровки. Не изменился — текст, участники и тайминги те же, и повторно разбирать звонок не нужно.
* `source_instance_id` — постоянный идентификатор набора данных модуля. Он переживает обновления и помогает понять, что данные те же самые, а не пересозданные.
* События не повторяются: достаточно запоминать идентификатор события вместе с `source_instance_id`.

{% hint style="info" %}
Все остальные запросы модуля (настройки, задания, диагностика) обслуживают его веб-интерфейс и для интеграций не предназначены.
{% endhint %}
