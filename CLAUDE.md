# Репозиторий документации docs.mikopbx.com

## Структура веток — критическая особенность

В этом репозитории **две независимые ветки**, каждая хранит документацию
на своём языке:

- `russian` — русская версия документации (GitBook space RU).
- `english` — английская версия документации (GitBook space EN).

**Ветки не связаны между собой и не должны мержиться.** Каждая ветка
живёт самостоятельно: у `russian` свой набор файлов на русском, у
`english` — свой набор файлов на английском. Это **не** копия одного
дерева с переводом — содержимое веток расходится по структуре,
скриншотам и формулировкам.

### Что это значит на практике

- **Никогда не делать `git merge russian` ↔ `english`** (и наоборот),
  даже частично. Это перемешает языки и поломает обе версии.
- **Не пытаться синхронизировать ветки через rebase/cherry-pick** между
  языками. Если по смыслу изменение должно быть в обеих версиях —
  применяйте его в каждой ветке **отдельно**, с переведённым текстом.
- **PR создаются по одному на каждую ветку**, цели мержа — `russian`
  → `origin/russian`, `english` → `origin/english`. Никаких кросс-мержей.
- **GitBook publish** настроен отдельно для каждой ветки на свой space.

### Обычный рабочий цикл для двуязычных обновлений

1. `git checkout russian` — внести RU-правки, закоммитить.
2. `git checkout english` — внести EN-эквивалент **вручную** (или
   скопировать заранее подготовленные drafts), закоммитить.
3. Запушить обе ветки независимыми коммитами.

Драфты часто готовятся заранее в отдельном репозитории (например,
`mikopbx/Core/sessions/tasks/.../docs-drafts/{ru,en}/`) и копируются
в нужную ветку по сценарию `APPLY.md`.

## Прочее

- Файлы документации — GitBook-flavored Markdown: блоки `{% hint %}`,
  `{% content-ref %}`, `<figure>` для иллюстраций, ассеты — в
  `.gitbook/assets/`.
- Главный файл навигации — `SUMMARY.md` (правится в обеих ветках
  параллельно, но с разными текстами заголовков).
- Основная (default) ветка на GitHub — `english`.
