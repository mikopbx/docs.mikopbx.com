# Облачная транскрибация

**Модуль облачной транскрибации** автоматически распознает записанные звонки MikoPBX на русском языке и сохраняет готовые расшифровки локально на станции. Подходящие записи отправляются в облачный сервис распознавания MIKO, а результат — текст разговора с репликами и таймкодами — доступен в интерфейсе модуля, в истории звонков и через REST API.

{% hint style="info" %}
Модуль полностью автономен: отдельное приложение-обработчик не требуется. Если аудиозаписи нельзя передавать во внешний сервис, используйте [Модуль локальной транскрибации](../module-local-speech-to-text/README.md).
{% endhint %}

{% hint style="warning" %}
Отправка записи на распознавание — платное действие: стоимость списывается с баланса вашей лицензии MIKO. До завершения первого запуска и активации модуль не отправляет провайдеру ни одной записи.
{% endhint %}

**Скриншот 1. Главный экран модуля**

### Как проходит обработка

1. Звонок завершается, и MikoPBX сохраняет запись разговора.
2. Модуль находит запись и проверяет правила отбора: направление звонка, сотрудники, номера, длительность, суточный лимит и число одновременных облачных задач.
3. Прошедшая отбор запись перекодируется в единый формат Ogg/Opus (48 кГц, 32 кбит/с), число каналов источника сохраняется.
4. Модуль отправляет запись в облачный сервис и создает задачу в локальной очереди.
5. Фоновый процесс периодически опрашивает сервис до готовности результата. В отложенном режиме обработка одной записи может занимать до 12 часов.
6. Готовая расшифровка нормализуется, сохраняется на станции, и для внешних модулей публикуется событие о новом транскрипте.

Если исход отправки не определен (например, оборвалась сеть в момент запроса), модуль никогда не повторяет отправку автоматически — это исключает повторное списание средств. Такие задачи попадают в группу «Требуют внимания», и повтор выполняется только вручную.

### Требования и совместимость

* MikoPBX **2026.1.223** или новее.
* Действующая лицензия MIKO с опцией облачной транскрибации и положительный баланс.
* Включенная запись разговоров для нужных маршрутов, очередей или сотрудников.
* Прямой исходящий доступ по HTTPS к `speech.mikolab.ru:443`. Настроенный на станции HTTP-прокси для запросов к сервису не используется: если интернет доступен только через прокси, модуль не сможет подключиться.
* Язык распознавания — русский.

### Установка модуля

1. Откройте веб-интерфейс MikoPBX.
2. Перейдите в раздел **Модули** → **Маркетплейс модулей**.
3. Найдите **Облачная транскрибация** и установите модуль.
4. Откройте список установленных модулей и включите модуль.
5. Нажмите кнопку настроек справа от версии модуля — откроется страница **Облачная транскрибация**.

### Первый запуск

Сразу после установки модуль не отправляет записи. Откроется мастер из трех шагов; пройти его может только администратор.

#### Шаг 1. Конфиденциальность

Модуль предупреждает, что выбранные записи звонков передаются на `speech.mikolab.ru` для распознавания. Транскрипты и записи остаются на станции. Подтвердите согласие кнопкой **Продолжить**.

#### Шаг 2. Подключение

Нажмите **Проверить подключение**: модуль проверит доступность API сервиса, авторизацию по лицензии и состояние баланса. Проверка не отправляет аудио и не создает платных задач. Если что-то не готово, устраните проблему и повторите проверку.

#### Шаг 3. Правила и активация

Проверьте правила отбора звонков (направления, сотрудники, лимиты) — на этом шаге доступны те же настройки, что и на вкладке **Настройки**. Подтвердите включение автоматического отбора и нажмите **Активировать модуль**. Первая отправка произойдет только после появления подходящей записи.

### Вкладка «Транскрипты»

Здесь собраны локально сохраненные результаты распознавания. Список фильтруется по периоду звонков (календарь или «Сегодня») и ищет по номеру, сотруднику или тексту расшифровки. В таблице отображаются дата, направление, контрагент, сотрудник, статус (полный или частичный), длительность и время обновления.

Карточка транскрипта содержит:

* реплики с таймкодами и ролями участников — сотрудник, клиент или неизвестный участник;
* встроенный проигрыватель с регулировкой скорости и скачиванием записи;
* поиск по репликам разговора;
* экспорт в **JSON** или **TXT**;
* удаление транскрипта (только администратор).

Нажатие на реплику переводит проигрыватель к соответствующему моменту записи.

**Скриншот 8. Карточка транскрипта с репликами и проигрывателем**

#### Разговоры с переводом

Карточка объединяет несколько записей одного звонка в хронологические этапы: у каждого этапа указаны участники, а внутренний участок показывается как внутренний разговор, а не как разговор с клиентом. Время у реплики отсчитывается внутри ее аудиофайла, а по окончании этапа проигрыватель переходит к следующей записи.

**Звонок** — общая длительность по CDR с учетом промежутков между записями; **Аудиозаписи** — приблизительная сумма длительностей файлов. Общая хронология доступна в сведениях о звонке.

#### Удаление транскрипта

Удаление необратимо и требует подтверждения администратора. CDR и исходная аудиозапись MikoPBX не удаляются; копиями данных у внешнего обработчика модуль не управляет. Повторное распознавание той же записи после удаления транскрипта — платное.

### Вкладка «Очередь»

На вкладке управляется локальная очередь задач. Доступны фильтр по статусу, период (1 день или все время), поиск по номеру или направлению и постраничная навигация.

| Группа фильтра        | Состояния задач                                                                                  |
| --------------------- | ------------------------------------------------------------------------------------------------ |
| **Ожидают**           | Найдена, Ожидает запись, Готова к отправке, Безопасное ожидание отправки                          |
| **Обрабатываются**    | Отправляется, Принята сервисом, Распознаётся                                                     |
| **Требуют внимания**  | Исход отправки неизвестен, Локальная ошибка, Ошибка сервиса, Некорректный результат, Обработка зависла, Истёк срок результата |
| **Завершены**         | Готово, Результат не сохранён после удаления, Отменена                                           |

По задаче доступна техническая информация: ID задачи, номер запуска (поколение), этап обработки, код ошибки, HTTP-код и тип сетевой ошибки, CDR ID, размер и формат аудио.

| Действие            | Когда доступно и что делает                                                                                                      |
| ------------------- | -------------------------------------------------------------------------------------------------------------------------------- |
| **Отменить задачу** | Только до начала загрузки аудио. Подтверждение не требуется.                                                                     |
| **Повторить задачу**| Явное платное подтверждение. Создает новое поколение задачи и может привести к повторному списанию. Автоматических повторов у модуля нет. |
| **Открыть транскрипт** | Переход к готовой расшифровке на вкладке «Транскрипты».                                                                       |

{% hint style="info" %}
Когда суточный лимит минут исчерпан, новые задачи ждут наступления следующих суток. Если администратор увеличит лимит, отправка возобновится сразу.
{% endhint %}

#### Правила для номеров

Правила включают или исключают номера из обработки. У каждого правила задаются направление (любое, входящее или исходящее), тип совпадения (точный номер или префикс), номер и действие (включить или исключить). Поддерживается до 200 правил, длина номера — до 32 символов.

#### Лимиты обработки

| Настройка                        | По умолчанию | Диапазон       | Назначение                                                                          |
| -------------------------------- | ------------ | -------------- | ------------------------------------------------------------------------------------ |
| **Минимальная длительность**     | `10 сек`     | 0–86400        | Звонки короче порога не отправляются.                                                |
| **Максимальная длительность**    | `3600 сек`   | до 86400       | Звонки длиннее порога не отправляются.                                               |
| **Суточный лимит**               | `600 мин`    | 1–100000       | Сколько минут аудио в сутки можно отправить на распознавание.                        |
| **Одновременных облачных задач** | `10`         | 1–100          | Сколько записей сервис распознает одновременно; остальные ждут в локальной очереди.  |

#### Раздел «Журнал»

**Журнал модуля** содержит очищенные технические события облачной транскрибации — без текстов разговоров, путей к записям и секретов. Доступны периоды 1, 3, 12 и 24 часа, фильтры по уровню и компоненту, полнотекстовый поиск и обновление списка.

В блоке **Инструменты поддержки** готовится диагностический архив для обращения в техподдержку. Архив собирается асинхронно, содержит только очищенные операционные данные и доступен для скачивания ограниченное время.

### Приостановка обработки

Кнопка **Приостановить обработку записей** в шапке модуля временно останавливает отбор и отправку новых записей — например, на время работ или при разбирательстве инцидента. Уже принятые сервисом задачи продолжают опрашиваться до готовности. Кнопка **Возобновить обработку записей** возвращает модуль в рабочий режим.

### Права доступа

Модуль регистрирует в ModuleUsersUI три права:

* **transcripts** — вкладки «Обзор» и «Транскрипты», просмотр расшифровок, проигрывание записей и экспорт;
* **settings** — правила отбора, режим распознавания и хранение;
* **system** — очередь задач, журнал, инциденты, аудит и диагностика всего модуля.

{% hint style="warning" %}
Активация модуля и подтверждение передачи данных внешнему сервису доступны только администратору: пользователям с правом `settings` состояние активации видно, но кнопки заблокированы. Право `system` открывает диагностику по всему модулю без фильтрации по звонкам конкретного сотрудника — выдавайте его только доверенным операторам.
{% endhint %}

### Конфиденциальность и безопасность

* Адрес сервиса и лицензионный ключ не являются настраиваемыми полями: системный лицензионный ключ не сохраняется в модуле и не записывается в журналы.
* Аудио отправляется только после явной активации и подтверждения внешней обработки администратором.
* Журналы модуля содержат только очищенные технические события; тексты транскриптов, пути к записям и идентификаторы операций провайдера в них не попадают.
* Организация самостоятельно отвечает за правовое основание передачи записей, информирование участников разговора и договорные отношения с внешним обработчиком.

### REST API

Базовый путь:

```
/pbxcore/api/v3/module-cloud-speech-to-text
```

Управляющие ресурсы требуют авторизации администратора. Основные ресурсы:

| Назначение                     | Endpoint                            |
| ------------------------------ | ----------------------------------- |
| Сводка и состояние             | `GET /dashboard`, `GET /health`     |
| Правила отбора                 | `GET/PATCH /rule-sets/current`      |
| Режим и хранение               | `GET/PATCH /settings`               |
| Проверка подключения           | `POST /connection-checks`           |
| Управление обработкой          | `GET/PATCH /processing-controls`    |
| Очередь задач                  | `GET /jobs`                         |
| Отмена и повтор задачи         | `POST /job-cancellations`           |
| Список транскриптов            | `GET /transcripts`                  |
| Экспорт транскрипта            | `GET /transcript-exports/{id}`      |
| Журнал модуля                  | `GET /logs`                         |
| Диагностические архивы         | `GET/POST /diagnostic-reports`      |
| Поиск транскрипта по звонку    | `GET /cdr-transcript-lookups`       |

#### Интеграции: call-transcripts

Внешние модули читают готовые транскрипты через два выделенных ресурса — `GET /call-transcripts` и `GET /call-transcript-events`. Эти ресурсы принимают только специальный ключ интеграции и отдают полный неизменяемый контракт расшифровки: сегменты, объединенные реплики и простой текст.

Идентификация построена так, чтобы после чистой переустановки модуля внешняя система не пересчитывала анализ заново:

* `call_id` — стабильный идентификатор звонка Asterisk (`linkedid`, либо `UNIQUEID`, когда `linkedid` пуст);
* `source_instance_id` — идентификатор установки модуля;
* `semantic_hash` — хеш содержимого расшифровки по профилю `call-transcript-analysis-v1`: совпадает, только если текст, участники и тайминги не изменились.

События `call-transcript.completed`, `call-transcript.updated` и `call-transcript.deleted` выдаются курсорной выдачей и идемпотентны. Публичная схема контракта — `call-transcript.v1`. После удаления транскрипта события больше не раскрывают `call_id` и хеши.
