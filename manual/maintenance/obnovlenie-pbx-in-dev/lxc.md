# Обновление LXC-контейнера

{% hint style="warning" %}
Рекомендуется производить обновления последовательно, «не перепрыгивая» через релизы и версии.
{% endhint %}

Эта инструкция предназначена для системного LXC-контейнера MikoPBX в Proxmox VE.

LXC отличается и от полноценной виртуальной машины, и от Docker. Корневая файловая система MikoPBX разворачивается из шаблона `lxc.tar.gz`, а конфигурация и записи подключаются к контейнеру отдельными mount points `/cf` и `/storage`.

{% hint style="danger" %}
Не запускайте обновление LXC через `.img` в разделе **Обновление PBX** и не подключайте ISO. IMG-обновлятор MikoPBX рассчитан на полноценный системный диск с загрузочным разделом и UUID разделов. У LXC такой дисковой структуры нет.
{% endhint %}

## Безопасный подход

Для LXC безопаснее не изменять корневую файловую систему работающего контейнера вручную, а развернуть новый контейнер из актуального `lxc.tar.gz`, перенести настройки и данные, проверить работу и только затем удалить старый контейнер.

Преимущества такого подхода:

* исходный контейнер остаётся доступен для быстрого возврата;
* не требуется записывать дисковый `.img` внутри LXC;
* новая версия получает актуальную корневую файловую систему и entrypoint;
* переключение выполняется только после проверки новой станции.

## Подготовка старого контейнера

1. Создайте резервную копию настроек средствами MikoPBX и скачайте её на компьютер администратора.
2. Отдельно сохраните записи разговоров и другие данные из `/storage`, если они должны переноситься в новый контейнер.
3. В Proxmox VE откройте старый CT → **Backup** → **Backup now** и создайте полный backup контейнера.
4. Запишите параметры старого CT:
   * hostname;
   * количество CPU и RAM;
   * IPv4/IPv6, bridge, VLAN и MAC-адрес;
   * DNS;
   * параметры mount points `/cf` и `/storage`;
   * дополнительные capabilities, включая `CAP_NET_ADMIN`, если она использовалась;
   * пароль и SSH-ключи.
5. Не удаляйте и не изменяйте старый контейнер до полной проверки новой версии.

{% hint style="warning" %}
Snapshot не заменяет backup. Snapshot зависит от исходного хранилища Proxmox, а backup можно восстановить отдельно.
{% endhint %}

## Загрузка нового шаблона

1. Откройте страницу [релизов MikoPBX](https://github.com/mikopbx/Core/releases).
2. Скопируйте ссылку на файл нужной версии с окончанием `lxc.tar.gz`.
3. В Proxmox VE выберите хранилище **local** → **CT Templates**.
4. Нажмите **Download from URL**.
5. Вставьте ссылку, нажмите **Query URL**, затем **Download**.
6. Дождитесь сообщения **TASK OK**.

## Создание нового контейнера

Создайте новый CT по инструкции [Установка MikoPBX в Proxmox LXC](../../../setup/hypervisor/proxmox/lxc.md), но учитывайте следующие правила:

1. Используйте **новый CT ID** — старый контейнер должен сохраниться.
2. Выберите скачанный шаблон новой версии `lxc.tar.gz`.
3. Создайте отдельные mount points:
   * `/storage` — для записей и пользовательских данных;
   * `/cf` — для конфигурации MikoPBX.
4. На время проверки назначьте другой IP-адрес, чтобы новый CT не конфликтовал со старым.
5. Повторите CPU, RAM, bridge, VLAN, DNS и необходимые capabilities старого контейнера.
6. Запустите новый CT и дождитесь появления IP-адреса в консоли.

{% hint style="info" %}
Не подключайте одновременно один и тот же writable mount point `/cf` или `/storage` к двум запущенным контейнерам. Это может привести к повреждению данных.
{% endhint %}

## Перенос настроек и данных

Рекомендуемый вариант — новая конфигурационная область `/cf` с восстановлением резервной копии MikoPBX.

1. Откройте web-интерфейс нового контейнера по временному IP-адресу.
2. Установите используемый вами модуль резервного копирования, если он не установлен.
3. Загрузите резервную копию старой станции и выполните восстановление.
4. Перенесите необходимые данные из старого `/storage` в новый `/storage` либо восстановите их из отдельной резервной копии.
5. Перезагрузите новый контейнер и убедитесь, что настройки сохранились.

Если объём записей велик, переносите Storage средствами Proxmox или файлового хранилища при остановленном старом контейнере. Способ зависит от типа Proxmox storage и поэтому не должен заменяться универсальной командой копирования.

## Переключение на новый контейнер

1. Завершите активные вызовы на старой станции.
2. Остановите старый CT.
3. Назначьте новому CT прежний IP-адрес либо переключите DNS/NAT на новый адрес.
4. Если использовался прежний MAC-адрес, убедитесь, что старый CT остановлен до запуска нового.
5. Запустите или перезагрузите новый CT.
6. Проверьте доступ к web-интерфейсу с рабочих сетей.

## Проверка после обновления

1. Проверьте версию MikoPBX в web-интерфейсе.
2. Убедитесь, что `/cf` и `/storage` подключены и доступны для записи.
3. Проверьте сотрудников, провайдеров, маршруты, модули и правила firewall.
4. Убедитесь, что телефоны и SIP-провайдеры зарегистрировались.
5. Выполните тестовые входящий и исходящий звонки.
6. Проверьте создание новой записи разговора.
7. Перезагрузите CT из Proxmox и повторно проверьте сеть и доступность web-интерфейса.

{% hint style="warning" %}
Работа firewall внутри LXC зависит от наличия `CAP_NET_ADMIN`. Если capability отсутствует, сетевые ограничения должны обеспечиваться Proxmox firewall и другими внешними средствами.
{% endhint %}

## Откат

Если новая станция работает некорректно:

1. Остановите новый CT.
2. Верните прежние IP-, DNS- или NAT-настройки старому CT.
3. Запустите старый контейнер.
4. Если старый контейнер был изменён, восстановите его из Proxmox backup.

Старый CT и его backup удаляйте только после нескольких дней стабильной работы новой версии и проверки резервного копирования.
